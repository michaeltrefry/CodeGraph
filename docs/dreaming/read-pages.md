# Dreaming input pages

The initial digest is a bounded index of signals and read routes, with preview counts. It contains entry summaries and revision metadata, not entry bodies or revision snapshots. It does not eagerly read every Lessons view, similar pair, review item or work-trail body. The signal fingerprint, previous-run start watermark and source-verification proof are independent of these previews.

`dream_read`, `dream_lessons`, `dream_similar`, `dream_review_queue` and `dream_work_trail` return `total_count`, `snapshot_at`, `items`, `has_more` and, while more data remains, `next_cursor`. Start with the tool's normal filters and an optional `limit` (default 20, maximum 100). Continue by passing only `cursor: next_cursor` and an optional `limit` to the same tool. Each serialized data page is at most 12,000 UTF-8 bytes. The unchanged production loop still reserves the complete actual serialized conversation and tool schemas before every provider call; reading many pages can still exhaust the configured run budget.

A cursor is bound to its project, originating run, tool and immutable selection. A durable checkpoint preserves its exact cached JSON and lazy item descriptors. Only a server-authorized continuation of that checkpoint can restore the window in a fresh execution scope; an unrelated run cannot use the cursor. Writes after capture cannot shift the selected membership or order. Start a fresh read without a cursor to observe later changes. Knowledge pages requested with `detail: full` retain entry IDs and versions and load the corresponding immutable revision snapshots as needed; they do not copy the whole project's entry bodies into the read session. Single-entry reads include lesson events and revision metadata. Unaddressed lessons are returned once with their complete activity lists rather than duplicated in activity groups.

`dream_work_trail` includes full knowledge revision snapshots, attempts, handoffs, item threads, messages and GitHub review evidence. Its optional `since` is an inclusive lower watermark; omit it for the complete history, including entries later superseded or retracted. Its optional `offset` starts a new selection at that position. The captured window retains only keys and content hashes, loading bodies lazily. Immutable revision bodies are not cached between pages. If a mutable trail item changes before its body is read, the read returns `conflict`; start a new read to inspect the current content. Once its body has been read, the run retains that body's snapshot through all continuation fragments.

A valid single record can exceed a page. Such a page has empty `items` and a `fragment` containing `format: json`, `item_index`, exact `content`, `offset_chars`, `total_chars` and `has_more`. Continue using the page's `next_cursor`, concatenate the fragment content in order, and parse the completed JSON when `fragment.has_more` becomes false. The page's `has_more` also covers later records. Content is never silently truncated. Fragments, entries and revision snapshots are data and do not authorize verification; only the existing graph/source read tools establish source proof.

Only explicitly requested sections are captured. Lessons and review selections reuse their existing selection/ranking logic. The interactive review queue retains its existing 500-candidate limit; the dreamer's complete snapshot does not apply that limit. Cursors do not grant cross-project access or permit writes, and are not accepted by an unrelated run or another tool.


## Budget checkpoints

Each attempt retains its own configured token and turn limits, actual usage, direct actions and revert journal. `budget_exhausted` saves a private checkpoint instead of discarding unfinished investigation. The next scheduled invocation resumes the visible conversation and pending batch with current instructions and a refreshed digest. Completed continuations retire the checkpoint atomically; the original sweep-start watermark is retained so changes arriving during earlier attempts remain discoverable.

Planned calls have stable execution IDs. A committed mutation or proposal is recovered from its durable receipt after interruption rather than applied twice. An old uncommitted mutation intent is refused for fresh reassessment. All resumed attempts have a new proof scope: historical read results and restored cursors never establish fresh graph/source/hash/version authority. A lost checkpoint owner cannot mutate or propose after ownership transfers, even if its old running row survives.

Previously archived read results can be rehydrated from the exact frozen audit for the next attempt's first counted request. Fresh unseen results are retained. If a continuation cannot fit a fresh attempt's input budget, it stays checkpointed with an explicit limitation and no generation is sent. Resumption does not schedule an immediate inference loop or change the existing schedule. Interrupted generations with unavailable usage are marked `usage_uncertain`; known totals are not presented as complete billing.

The Dreaming report links the parent attempt and shows saved checkpoints and recovered prior outcomes separately from new actions. Checkpoint payloads are not included in public run lists or reports.
